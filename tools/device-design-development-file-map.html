Design and Development File and Medical Device File - Building the Records That Prove Conformity

The Quality Management System Regulation no longer uses the terms design history file, device master record, or device history record. FDA concluded their requirements are covered by records such as the medical device file (ISO 13485 clause 4.2.3) and the design and development file (clause 7.3.10), with additional record requirements in 21 CFR 820.35. This map follows the pathway from defining the file structure through building each file, adding the FDA-specific record content, and keeping the files current and inspection ready.

21 CFR 820.35
ISO 13485:2016 4.2.3
ISO 13485:2016 7.3.10

Medical Device File

A compilation of records and documents for each medical device type demonstrating conformity to regulatory requirements. Successor to the device master record.

Basis: Clause 4.2.3

Design and Development File

The compilation of records for a device type or family showing the design met its requirements, including changes. Successor to the design history file.

Basis: Clause 7.3.10

Control of Records

ISO 13485 record control plus the additional content FDA requires for complaint records, servicing records, and UDI.

Basis: Clause 4.2.5 and 21 CFR 820.35

Production Records

Batch or unit evidence that each device was made to its specifications. The QMSR no longer uses the term device history record.

Basis: Clause 7.5.1 and 820.35(c)

Legacy Terms to QMSR Records (Overview)

Device Master Record

The term is gone. The content is now carried by the medical device file.

ISO 13485:2016 4.2.3

Design History File

The term is gone. The content is now carried by the design and development file.

ISO 13485:2016 7.3.10

Device History Record

The term is gone. Batch or unit production evidence is now covered by production records and the UDI record requirement.

ISO 13485:2016 7.5.1; 21 CFR 820.35(c)

When a File Has Gaps (Overview)

Identify the gap Compare the file with its index and the clause requirements to find the missing or inconsistent record.
Look for the record elsewhere Check whether the record exists in another system or file and can simply be linked or indexed.
Create or recover under control Where the record does not exist, create it with a documented rationale and approval, never backdated.
Prevent recurrence Update the file index, procedure, or owner assignment so the gap cannot reappear.

What FDA Adds Beyond ISO 13485 (Overview)

Complaint records Contents set for reviewed, evaluated, and investigated complaints, including device identifiers and any reply to the complainant.
Servicing records Device name, identifiers, service date, person servicing, service performed, and test and inspection data.
UDI recording The UDI recorded for each device or batch of devices.
Confidentiality marking Records the manufacturer considers confidential may be marked to aid FDA in disclosure decisions.

File Quality Elements

Defined File Scope Each device type or family has a named medical device file and design and development file.
Legacy Term Mapping Old terms are mapped to the ISO clauses so records are findable under either name.
Complete Index Every record in the file is indexed with its location and owner.
Design to Specification Traceability Final specifications trace back to approved design outputs.
Production Record Linkage Production records show conformity with the specifications in the file.
FDA Record Content Complaint, servicing, and UDI records carry every element 21 CFR 820.35 requires.
Controlled Change File content changes are reviewed and approved before they take effect.
Retrieval and Retention Records are legible, retrievable, and retained for the required period.

Never do this

Rename the file and assume the content requirement went away. Let design records sit in personal folders instead of the file. Backdate a missing record. Record complaints or servicing without the elements 21 CFR 820.35 requires. Change file content without approval.

Medical device file vs design and development file

The medical device file holds what is needed to make and release the device to specification. The design and development file holds how the design was developed and shown to meet its requirements, including changes. Final specifications connect the two at design transfer.

Old names, same substance

FDA considers the former DHF, DMR, and DHR requirements covered by the ISO 13485 records. A cross-reference that maps old names to the ISO clauses, plus filling any content gaps, is generally a lighter path than restructuring every record.

Key regulations
